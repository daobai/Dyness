# OTA / 固件升级测试用例生成（禅道 CSV）

## 目标
把 OTA / 固件升级相关需求（PRD / 原型 / 口述 / 禅道需求）拆解成**细致粒度**的测试用例，输出一份**禅道可导入的 CSV**。OTA 涉及「云端固件管理 → 升级任务下发 → 设备侧升级执行 → 版本回传」整条链路，用例以**升级主链路为主线**，重点覆盖**可靠性（断点续传、失败回滚、离线补发）**。

## 背景：OTA 升级的是什么
储能设备分布广、无法现场刷机，OTA（Over-The-Air）通过云平台远程升级固件。升级对象分两层：
- **通信模块 / 采集器固件**：采集逻辑、协议适配、上报优化
- **设备（电池 / BMS / PCS）固件**：保护策略、充放电逻辑、新增工作模式

升级链路：
```
云端上传固件包 → 配置目标设备/批次 → 下发升级任务
  → 设备下载固件（可断点续传）→ 校验完整性(MD5/校验和)
  → 进入升级状态 → 刷写 → 重启 → 回传新版本号 → 生成升级记录
```

## 输出格式：禅道 CSV

首行为表头（禅道标准中文字段名），后续每行一条用例。

### 标准字段
| 字段 | 说明 | 必填 |
|------|------|------|
| 所属产品 | 产品名称；未给则填「默认产品」 | 否 |
| 所属模块 | 模块路径；系统模块用 `名称(#ID)` | 否 |
| 用例标题 | 简洁描述测什么 | 是 |
| 前置条件 | 执行前需满足的状态，可空 | 否 |
| 步骤 | 编号步骤，多步换行 | 是 |
| 预期 | 与步骤一一对应的编号预期，多步换行 | 是 |
| 优先级 | 1 / 2 / 3 / 4（1 最高） | 否 |
| 用例类型 | 功能测试 / 接口测试 / 性能测试 / 安全测试 / 兼容测试 / UI测试 / 安装部署 / 配置相关 / 其他 | 是 |
| 适用阶段 | 冒烟测试 / 功能测试 / 集成测试 / 系统测试 / 验证阶段 | 否 |
| 相关需求 | 需求标题或 ID | 否 |
| 关键词 | 逗号分隔，便于检索 | 否 |

> 若用户提供自己禅道版本的「导出模板」CSV，**以其表头为准**替换上表，保持字段名完全一致。

### 步骤与预期书写规则
- 步骤每步换行：`1. 上传固件包`、`2. 选择目标设备`
- 预期与步骤**一一对应**：`1. 固件包上传成功`、`2. 设备列表正确显示`
- 某步无预期时，预期对应行留空（保持序号对齐）
- 单元格内含换行时，用英文双引号包裹整个单元格

### CSV 编码
默认 UTF-8（无 BOM）；禅道导入中文乱码则改 GBK。

## 粒度要求（细致）
每个功能点、每个输入项都要拆开，至少覆盖：
- **正常流**：主路径成功场景
- **边界值**：版本号边界、固件包大小上限、批量升级数量上限
- **异常 / 非法**：损坏包、空包、格式错误、超长、重复版本、必填缺失
- **状态 / 权限**：不同角色、不同设备状态（在线/离线/升级中）下的行为
- **关联 / 联动**：固件与机型匹配、版本与升级条件联动、先后顺序、重复提交

## OTA 端侧重点
- **固件包管理**：上传（格式/大小/类型/损坏包/空包）、校验和(MD5)、固件增删改查、版本号规则、固件与机型/产品型号匹配
- **升级任务**：单台/批量/全部、立即/定时升级、灰度分批、升级条件（仅低于目标版本才升）
- **升级执行**：下载(断点续传)、升级中状态（页面/设备状态、升级期间禁止操作）、升级成功/失败、升级记录列表
- **可靠性（核心）**：断点续传、失败回滚（退回旧版本不变砖）、离线补发、升级中掉电/断网/重启、并发多台同时升级、网络超时/抖动
- **版本管理**：升级后版本号正确回传、跨版本升级、回滚/降级、重复升级拦截、版本不匹配拦截
- **安全与权限**：角色权限（谁能下发升级）、越权、跨品牌/区域升级拦截

## 端到端（E2E）设计重点
- 以**升级主链路**为主线：上传固件 → 创建任务 → 下发 → 设备下载/校验/升级 → 重启 → 版本回传 → 升级记录
- **状态流转**：待升级 → 下载中 → 升级中 → 升级成功 / 失败 / 回滚
- **链路异常注入**：下载中断、升级断电、设备离线、网络超时后的补偿 / 重试 / 回滚
- **升级前后一致**：升级后设备功能正常、历史数据不丢、版本号在各端一致

## 输出
1. 直接给出完整 CSV（表头 + 所有用例）
2. 用户要求落盘时，用 Write 保存为 `.csv`（UTF-8）
3. 结尾附统计：用例总数、按类型 / 优先级分布
