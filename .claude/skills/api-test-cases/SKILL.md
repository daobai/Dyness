# API 测试用例生成（禅道 CSV）

## 目标
把接口需求（接口文档 / Swagger / 口述）拆解成**细致粒度**的测试用例，输出一份**禅道可导入的 CSV**。项目多为**端到端**场景，接口用例以**接口串联链路**为主线设计。

## 输出格式：禅道 CSV

首行为表头（禅道标准中文字段名），后续每行一条用例。

### 标准字段
| 字段 | 说明 | 必填 |
|------|------|------|
| 所属产品 | 产品名称；未给则填「默认产品」 | 否 |
| 所属模块 | 模块路径；系统模块用 `名称(#ID)` | 否 |
| 用例标题 | 简洁描述测什么 | 是 |
| 前置条件 | 执行前需满足的状态，可空 | 否 |
| 步骤 | 编号步骤，多步换行 | 是 |
| 预期 | 与步骤一一对应的编号预期，多步换行 | 是 |
| 优先级 | 1 / 2 / 3 / 4（1 最高） | 否 |
| 用例类型 | 功能测试 / 接口测试 / 性能测试 / 安全测试 / 兼容测试 / UI测试 / 安装部署 / 配置相关 / 其他 | 是 |
| 适用阶段 | 冒烟测试 / 功能测试 / 集成测试 / 系统测试 / 验证阶段 | 否 |
| 相关需求 | 需求标题或 ID | 否 |
| 关键词 | 逗号分隔，便于检索 | 否 |

> 若用户提供自己禅道版本的「导出模板」CSV，**以其表头为准**替换上表，保持字段名完全一致。

### 步骤与预期书写规则
- 步骤每步换行：`1. 调用 POST /api/login`、`2. 传入正确账号密码`
- 预期与步骤**一一对应**：`1. 返回 200`、`2. 返回 token 且用户信息正确`
- 某步无预期时，预期对应行留空（保持序号对齐）
- 单元格内含换行时，用英文双引号包裹整个单元格

### CSV 编码
默认 UTF-8（无 BOM）；禅道导入中文乱码则改 GBK。

## 粒度要求（细致）
每个接口、每个参数都要拆开，至少覆盖：
- **正常流**：主路径成功场景
- **边界值**：最小值 / 最大值 / 临界 ±1、长度边界、空值、null、空格
- **异常 / 非法**：类型错误、格式错误、特殊字符、超长、重复、必填缺失
- **状态 / 权限**：不同角色、越权、不同业务状态
- **关联 / 联动**：字段依赖、先后顺序、幂等与重复提交

## 接口测试设计要点（与自动化数据保持一致）

> 边界值 / 等价类 / 枚举 / 异常场景的设计规范，与 `api-testdata` skill 保持一致；禅道用例与自动化测试数据共用同一套设计方法。

### 参数取值：边界值 + 等价类，不照搬文档示例
- **禁止照搬文档示例值**——示例值可能超范围或笔误（如 `powerLevelSetting` 示例 `103` 超出声明范围 700~2000、`gridPowerLimitValue` 示例 `3000` 超出 0~800）。一律按字段「取值范围 / 枚举 / 步长」重新设计取值。
- **等价类代表值**：有效类内取中间值（范围 700~2000 → `1000`）。
- **边界值**（合法，预期成功）：最小值、最大值（`700`、`2000`）。
- **边界外**（非法，预期参数错误）：最小-1、最大+1（`699`、`2001`）。
- **步长约束**：文档声明「每 N 一档」时，补非挡位值（每 10W 一档 → `705`）。
- **枚举参数**：每个合法取值都要覆盖（`safetyCountry` 0/2/37/43/46/106 逐值验证）。
- **嵌套字段**：注意字段层级（如 `gridPowerLimitGroup.gridPowerLimitValue`）。

### 异常 / 特殊参数
- 资源不存在（`deviceSn` 不存在）
- 必填缺失（缺必填参数）
- 空字符串 / null / 类型错误（数字传字符串、字符串传数字）
- 格式错误（时间 `HH:mm`、`HH:mm-HH:mm` 等）
- 特殊字符 / 超长

### 预期结果（业务码 code）
- 正常 / 合法参数 → `code=200`（success）
- 参数错误（越界 / 类型错误 / 必填缺失）→ `code=500`（Invalid Parameter）
- 未授权 → `code=401`（Unauthorized）

### 断言与结果判定
- **断言严格以接口文档为准**：实际返回与文档不一致时，**不改断言迁就实际**，保持用例失败/待确认，由人工与开发确认是文档问题还是实现问题。
- 结果三分类：通过（响应与文档一致）/ 待确认（code 正常但字段与文档不一致）/ 不通过（HTTP 非 200、code 非预期、请求异常）。

### 机型差异
- 机型：AquaVolt / AquaVolt_LV / SolarCube。
- 文档标注「某某系列：无」的字段，按机型区分，注明字段适用机型；某字段仅部分机型返回时，用例标注适用机型。
- **下发类接口**：不同机型支持的参数不同（如 `SetLoadControlSetting` 仅 SolarCube、`SetPeakControlSetting` AquaVolt_LV 无、`SetBatterySetting` 的 `batteryOffGridChargeLimit` 仅 SolarCube）。按机型区分参数适用性：字段级差异用 `[机型]` 前缀标注（执行时自动裁剪），整个接口仅某机型有意义时按机型拆分用例，不要一条用例覆盖所有机型。

## API 端侧重点
- **参数**：必填 / 选填、类型、格式（日期 / 手机号 / 邮箱）、边界值、长度、空值 / null、特殊字符
- **鉴权**：无 token / 过期 / 无效 / 无权限 / 越权访问
- **返回**：状态码、业务错误码、message 文案、返回结构字段类型
- **幂等与重复**：重复提交、重复调用结果一致
- **并发与超时**：并发请求、超时、限流
- **性能**：响应时间、大数据量

## 端到端（E2E）设计重点
- 以**接口串联链路**为主线（如 登录 → 查询库存 → 下单 → 支付 → 回调 → 查询订单）
- 上下游数据流转：上游接口产出作为下游输入，字段一致、类型匹配
- 状态流转：订单 / 流程状态在各接口间正确推进与回退
- 链路异常注入：某环节超时 / 失败 / 返回异常时，后续环节的补偿、回滚、重试
- 数据准备与清理，保证链路可重复执行

## 输出
1. 直接给出完整 CSV（表头 + 所有用例）
2. 用户要求落盘时，用 Write 保存为 `.csv`（UTF-8）
3. 结尾附统计：用例总数、按类型 / 优先级分布
