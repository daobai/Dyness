# Web 测试用例生成（禅道 CSV）

## 目标
把 Web 端需求（PRD / 原型 / 口述）拆解成**细致粒度**的测试用例，输出一份**禅道可导入的 CSV**。项目多为**端到端**场景，用例以完整业务链路为主线设计。

## 输出格式：禅道 CSV

首行为表头（禅道标准中文字段名），后续每行一条用例。

### 标准字段
| 字段 | 说明 | 必填 |
|------|------|------|
| 所属产品 | 产品名称；未给则填「默认产品」 | 否 |
| 所属模块 | 模块路径；系统模块用 `名称(#ID)` | 否 |
| 用例标题 | 简洁描述测什么 | 是 |
| 前置条件 | 执行前需满足的状态，可空 | 否 |
| 步骤 | 编号步骤，多步换行 | 是 |
| 预期 | 与步骤一一对应的编号预期，多步换行 | 是 |
| 优先级 | 1 / 2 / 3 / 4（1 最高） | 否 |
| 用例类型 | 功能测试 / 接口测试 / 性能测试 / 安全测试 / 兼容测试 / UI测试 / 安装部署 / 配置相关 / 其他 | 是 |
| 适用阶段 | 冒烟测试 / 功能测试 / 集成测试 / 系统测试 / 验证阶段 | 否 |
| 相关需求 | 需求标题或 ID | 否 |
| 关键词 | 逗号分隔，便于检索 | 否 |

> 若用户提供自己禅道版本的「导出模板」CSV，**以其表头为准**替换上表，保持字段名完全一致。

### 步骤与预期书写规则
- 步骤每步换行：`1. 打开登录页`、`2. 输入正确账号密码`
- 预期与步骤**一一对应**：`1. 页面正常显示`、`2. 输入框接受输入`
- 某步无预期时，预期对应行留空（保持序号对齐）
- 单元格内含换行时，用英文双引号包裹整个单元格

### CSV 编码
默认 UTF-8（无 BOM）；禅道导入中文乱码则改 GBK。

## 粒度要求（细致）
每个功能点、每个输入项都要拆开，至少覆盖：
- **正常流**：主路径成功场景
- **边界值**：最小值 / 最大值 / 临界 ±1、长度边界、空值、空格
- **异常 / 非法**：类型错误、格式错误、特殊字符、超长、重复、必填缺失
- **状态 / 权限**：不同角色、不同状态下的行为
- **关联 / 联动**：多字段联动、先后顺序、重复提交

## Web 端侧重点
- **页面元素**：按钮 / 输入框 / 下拉 / 单选 / 多选 / 上传的展示与可用性
- **表单校验**：必填、格式、长度、边界、特殊字符、前后端双重校验
- **跳转与链接**：页面跳转、返回、新窗口、外链、死链
- **浏览器兼容**：Chrome / Edge / Firefox 等与不同分辨率
- **权限与会话**：登录态、角色权限、会话超时、cookie / token 传递
- **交互**：弹窗、提示、loading、分页、搜索、排序、刷新、重复提交

## 端到端（E2E）设计重点
- 以**完整用户旅程**为主线（如 注册 → 登录 → 浏览 → 下单 → 支付 → 查看结果）
- 跨页面状态一致性：上一步的选择在下一步正确传递与回显
- 登录态 / 会话贯穿整条链路，不中断、不丢失
- 链路关键节点注入异常：某页加载失败、接口超时、支付中断时后续如何表现
- 数据准备与清理，保证用例可独立、可重复执行

## 输出
1. 直接给出完整 CSV（表头 + 所有用例）
2. 用户要求落盘时，用 Write 保存为 `.csv`（UTF-8）
3. 结尾附统计：用例总数、按类型 / 优先级分布
